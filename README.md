# 言葉 Kotoba

以阅读为中心的日语学习系统：读原文、拆难句，把读到的词和语法变成卡片，
用打字复习记住读音。

生词不是从词表里背来的，是从你真读过的文章里来的。

线上：<https://kotoba.work>

## 一条线：读 → 拆 → 记 → 到

| | 页面 | 做什么 |
|---|---|---|
| **读** | 阅读 | 存下读过的文章，全文自动注上振り仮名 |
| **拆** | 阅读 / 拆解 | 选中看不懂的一段，模型逐句讲翻译、活用和语法 |
| **记** | 卡片 / 复习 | 拆出来的东西勾一勾变成卡片，间隔重复，打字考读音 |
| **到** | 彼岸 | 离目标那天还有多久，每天做了多少 |

导航栏「首页 阅读 拆解 卡片 彼岸」就是这条线的顺序。各部分不是孤立的功能：
读的时候选中一段就地拆解，拆完勾选直接建卡，复习和读文章的记录一起
画在彼岸的日格子里。

## 读：阅读

「阅读」页存你读过的文章，点进去读。

保存时会**给全文加上振假名**：正文按段落切块、并行调模型注音，再拼回去，
换行和空行原样保留。某一块注不上（模型改了正文，或者请求失败）就用原文，
不会因为注音失败丢掉文章 —— 存完会告诉你有几段是原样存的。

后端会校验模型只是插入了注音：把注音剥掉必须和原文一字不差，对不上就退回
原文。让模型重写整段正文是有风险的，它可能顺手改字删句，而那种错误读者
根本发现不了。

读的时候**选中任意一段文字，底部会弹出拆解结果**，勾选就能建成卡片 ——
读、查、记在同一页闭环。宽屏上拆解结果放在右侧栏，不挡正文。

- **改文章**：文章页「编辑」。编辑框里是去掉注音的纯文本；保存时只有改过的行
  重新注音，没动的行沿用原来的读音 —— 改一个错字不会把整篇重注一遍。
- **删文章**：要点两下，第一下只是问一句。
- **列表**：每页 20 篇，按标题搜索，翻页和搜索都在后端做。页码和搜索词写在地址栏里
  （`/reading?page=3&q=nhk`），点进一篇再回来还停在原来那页。
- **上一篇 / 下一篇**：文章页底部，顺序和列表一样（保存时间倒序）。

## 拆：AI 拆解

「拆解」页：粘一段日语进去，模型逐句给出中文翻译、动词、外来语和语法点，
每条都能勾选，一键变成卡片（走的是批量导入那条路，重复的会自动跳过），
可以选存进哪个包。阅读页里选中拆解用的是同一套逻辑（`useAnalysis`）。

- **动词**：句中每个动词和形容词都列，原形也算。除了这句里的活用为什么这么用，
  还有自动词 / 他动词，以及这个词本身怎么用：带什么助词、固定搭配
  （「やむを得ない」）、自他对应的另一半（止む ↔ 止める）。
- **外来语**：给出英文。不是英语来源的（アルバイト 来自德语 Arbeit）、和製英語
  （サラリーマン = salary + man）会注明；和英文原意有偏差的会点一句
  （マンション 是公寓，不是豪宅）。

模型偶尔会在完整的 JSON 后面多吐一个括号，解析时只读第一个完整的对象，
不会因为这一个字符丢掉整次结果；中间真坏了的照样报错。

### 配模型服务

要用拆解和注音得配一个模型服务。支持两种，都只从环境变量读 key：

#### OpenAI 兼容接口（默认）

百炼（通义）、DeepSeek、智谱都是这一套，区别只在 base-url 和 model。
以百炼为例：

    export ANALYZE_BASE_URL=https://你的WorkspaceId.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
    export ANALYZE_API_KEY=sk-...
    export ANALYZE_MODEL=qwen3.7-plus
    cd backend && ./mvnw spring-boot:run

base-url 填到 `/v1` 为止，不要带 `/chat/completions`。百炼的地址带工作空间 id，
在控制台创建 key 的页面能看到；key 和地址是绑定区域的，别混用。

#### Anthropic

    export ANALYZE_PROVIDER=anthropic
    export ANTHROPIC_API_KEY=sk-ant-...

注意 Anthropic 的 API 额度和 Claude.ai 的订阅是两套账，要在 Console 的
Plans & Billing 里单独充值。

#### 说明

没配 key 也不影响别的：应用照常启动，只有 `/api/analyze` 回 503。

两条路共用同一份 JSON schema，从 `Analysis` 那几个 record 推出来
（`AnalysisSchema`）—— 改拆解的输出格式只要改 record，两边自动跟上。

## 记：卡片与复习

卡片可以从四个地方来：拆解结果勾选、卡片页手动加、批量粘贴（一行一张，
Tab 或逗号分隔）、导入 Anki 牌组。

### 分包

卡片按「包」组织。手动新建的卡片进当前选中的包（选「全部」时进默认包）；
导入 Anki 包会按包名新建一个包。

包名可以随时改（卡片页选中某个包 → 重命名）。删包会连里面的卡片一起删掉，
同样要点两下确认。

同一个词在不同包里可以各存一张，进度互不影响 —— 唯一约束是「包 + 正面」，
所以重复导入同一个包是安全的（会跳过），换个包名导入则会另存一份。

卡片页每页 50 张，搜索在全部卡片里找，正反面一起比，注音剥掉再比
（搜「勉強」能找到 `勉強[べんきょう]`）。

### 复习

首页「开始复习」把全部到期的卡片混在一起，也能按包单独复习。评分三档：
忘了 / 一般 / 记住了，间隔按 SM-2 的思路算（`UserCardState`）。

复习有两种模式，顶部切换，会记住上次用的：

- **打字**（默认）：看正面，输入读音。罗马字边打边变成假名（`wanakana`），用系统
  日语输入法直接打假名也行。打对了显示背面、默认「记住了」，回车即可；打错了显示
  答案，**要照着打对一遍才能进下一张**，这张记为「忘了」。片假名和平假名、
  「すーぱー」和「すうぱあ」都算对。打字时有合成的按键声，可以关。
- **翻卡**：看正面，想一想，翻过来自己评分。没有读音的卡在打字模式下也自动翻卡。

### 读音

打字模式拿卡片的「读音」字段对答案。几个读音用 ／ 隔开（今日：きょう／こんにち），
对上任意一个都算对。全假名、整句、语法句型的卡不考读音。

- **建卡时自动猜**，不调模型：先看正面的注音（`食[た]べる` → たべる），再看背面
  开头的假名（Anki 词汇包常见的「はんだん 名詞 判断…」）。背面那串还要和正面的
  送り仮名对得上才算，免得把碰巧是假名的词当成读音。
- **补读音**：规则猜不出来的，卡片页会提示「N 张卡还没有读音」。点「补读音」后按批
  处理，每批问一次模型；模型给的读音同样要核对，对不上的留给你手动填。
- **手动改**：卡片页「编辑」里有读音一栏，同样罗马字自动转假名。

### 导入 Anki 牌组

卡片页 →「从 Anki 导入…」→ 选 `.apkg` 文件。解析全在浏览器里做（`jszip` 解包，
`sql.js` 读包里的 SQLite），只有映射好的正反面文本会发给后端，媒体文件不上传。

选好哪个字段当正面、哪些字段拼成背面，旁边有实时预览。`[sound:...]`、`<img>`
等标记会被去掉；同一个包重复导入是安全的（重复的词会跳过）。

#### 振り仮名

包里的 `<ruby>` 注音会存成 Anki 的方括号记法 `諦[あきら]める`，显示时由
`Furigana` 组件渲染成真正的振り仮名 —— 假名排在汉字上方，而不是挤在括号里。
手动建卡也能用这个记法，正面输入 `勉強[べんきょう]` 就会带注音。

默认映射把**不带注音**的字段放正面（不剧透读音），背面放读音、词性、释义和
带注音的例句，各段之间换行。不满意就在导入界面上重新勾。

Anki 2.1.50 之后导出的包用 zstd 压缩（`collection.anki21b`），浏览器里解不了 ——
导出时勾选「支持旧版 Anki」即可。

## 到：彼岸

彼岸是要抵达的那一天，比如 JLPT 考试日。立好目标后，每个页面的导航上方都写着
「还剩几周几天」。

彼岸页把这段时间铺开：一条河从此岸画到彼岸，沿途标着要经过的节气和满月；
下面一天一格，走过的格子按那天复习和读文章的数量上色。日期按你所在的时区算
（东八区深夜复习的卡算当天）。

## self

`/self` 是一个单独的随笔页，和 Kotoba 不共用页头和样式。谁都能读，只有配置里的
主人（`SELF_OWNER`，默认 `keshi`）能写、改、删。长文在阅读器里打开。

## 技术栈

- 前端：React 19 + TypeScript + Vite + Tailwind CSS 4
- 后端：Spring Boot 4.1 + Java 21，Spring Security + Spring Session JDBC
- 数据库：PostgreSQL 16，表结构由 Flyway 管（`backend/src/main/resources/db/migration`）
- 模型：OpenAI 兼容接口（百炼、DeepSeek、智谱等）或 Anthropic

## 本地启动

先起数据库：

    docker compose up -d

后端（跑在 http://localhost:8080，表结构启动时自动迁移）：

    cd backend
    ./mvnw spring-boot:run

前端（跑在 http://localhost:5173，`/api` 转发到后端）：

    cd frontend
    npm install
    npm run dev

后端的集成测试连的是这个本地库，跑测试前也要先 `docker compose up -d`。

## 登录

第一次用要先注册：打开前端 → 「注册」→ 填用户名和密码（至少 8 位）。
登录后点导航上的用户名进账号页：改密码、绑邮箱、绑 GitHub、看/踢登录设备。

- **会话**：服务端 session + cookie，保留 30 天。session 存在 Postgres 的
  `spring_session` 表里（Spring Session JDBC），后端重启、发版都不会把人踢下线。
- **CSRF**：cookie 是 `SameSite=Lax`，写请求要带 `X-XSRF-TOKEN` 头（值来自
  `XSRF-TOKEN` cookie），`api.ts` 的 `apiFetch` 统一处理。新写的请求别直接用 `fetch`。
- **限流**：同一 IP 对同一账号连错 5 次锁 15 分钟；每个 IP 10 分钟最多 30 次登录、
  1 小时最多注册 5 次、发 5 封邮件。计数在内存里，单实例够用。
- **找回密码**：要先在账号页绑定并验证邮箱。没配 SMTP 时这个功能自动隐藏；
  本地想走通流程，启动后端时加 `MAIL_LOG_LINKS=true`，邮件里的链接会打在日志里。
- **GitHub 登录**：配了 `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` 才出现。
  本地开发的 OAuth App callback 填 `http://localhost:5173/api/login/oauth2/code/github`。

没有密码的账号（V2 迁移留下的 `keshi` 占位行、GitHub 建的号）**不能**再靠同名注册
「认领」—— 那等于谁先来谁拿走。要给这种账号设密码，直接在库里写哈希：

    read -rs PW && htpasswd -bnBC 10 "" "$PW" | tr -d ':\n'; unset PW
    # 把输出的 $2y$10$... 填进去
    UPDATE app_user SET password_hash = '$2y$10$...' WHERE username = 'keshi';

忘了密码又没绑邮箱，也是这个办法。
